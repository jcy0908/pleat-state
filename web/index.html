02

Model / 무엇을 남기고 무엇을 버렸는가

실제 직물 전체를 재현하지 않는다. 질문에 답하는 데 필요한 관계만 남겨, 조작과 결과 사이의 거리를 짧게 만든다.

A—01

입자

위치와 이전 위치를 가진 점. 상단 경계는 고정하고 나머지는 중력과 횡력에 반응한다.

A—02

제약

가로·세로·대각 연결이 이웃 거리를 되돌린다. 장력 값은 복원 강도를 조정한다.

A—03

접힘

주기와 깊이가 초기 형상을 정의한다. 주름은 텍스처가 아니라 시작 조건이다.

A—04

시간

작은 시간 간격으로 적분하고 제약을 반복한다. 불안정한 큰 도약은 허용하지 않는다.

MODEL BOUNDARY

굽힘 강성, 섬유 방향성, 충돌, 마찰, 공기역학은 아직 포함하지 않았다. 그러므로 이 결과는 ‘직물 예측’이 아니라 ‘힘의 관계를 보는 조작 가능한 가설’이다.

03

Evidence chain / 관찰을 결정으로 연결하기

  1. 01

    Evidence

    접힘 깊이를 바꾸면 같은 외력에서도 복귀 경로와 에너지 표시값이 달라진다.

    현재 모델 안에서 장력은 고정하고 접힘 깊이만 바꿔, 수치와 형상의 변화를 나란히 관찰한다.

  2. 02

    Interpretation

    형태의 차이는 표면 장식보다 초기 조건의 차이에 가깝다.

    ‘예쁜 주름’을 고르는 대신, 힘이 남고 빠져나가는 경로를 인터페이스의 중심으로 둔다.

  3. 03

    Decision

    프리셋보다 연속 제어를 먼저 보여준다.

    사용자는 완성된 장면을 소비하지 않고 장력·감쇠·중력 사이의 긴장을 직접 만든다.

  4. 04

    Implementation

    C++ 상태를 복사하지 않고 메모리 뷰로 그린다.

    WebAssembly 메모리의 위치 배열을 Canvas가 읽어, 계산과 표현의 경계를 명시한다.

이 체인은 현재 모델 내부의 관찰을 설명한다. 사람 대상 평가나 실제 소재 실험의 결론으로 확장하지 않는다.

04

Alternatives / 선택하지 않은 것도 설계다

쟁점 검토한 대안 선택 이유와 대가
적분 명시적 Euler Verlet 계열 위치 제약과 결합하기 단순하다. 대신 정밀한 물성 추정에는 적합하지 않다.
실행 JavaScript 전용 C++ → WASM 핵심 모델을 브라우저 밖에서도 시험한다. 빌드 경로와 경계 관리 비용이 생긴다.
표현 WebGL 재질 2D Canvas mesh 광택보다 구조를 읽기 쉽다. 깊이와 충돌 표현은 제한적이다.
제어 완성 프리셋 중심 연속 파라미터 원인과 결과를 탐색하게 한다. 처음 보는 사람에게는 설명 부담이 늘어난다.

05

Failure log / 실패를 숨기지 않는 인터페이스

F—01 / EXPLOSION

큰 시간 간격에서 망이 화면 밖으로 발산했다.

변경: 프레임 간격을 제한하고 고정된 작은 단계로 나눴다.

남은 위험: 극단적인 포인터 입력에서는 국소 변형이 여전히 커질 수 있다.

F—02 / FALSE DEPTH

명암이 강할수록 물성이 정교해 보이는 착시가 생겼다.

변경: 광택과 그림자를 걷고 면·선·수치만 남겼다.

남은 위험: 2D 투영은 접힘의 앞뒤 관계를 완전히 설명하지 못한다.

F—03 / CONTROL NOISE

모든 내부 값을 노출하자 질문보다 조작이 앞섰다.

변경: 해석 가능한 여섯 값만 남기고 세 상태를 기준점으로 제공했다.

남은 위험: 각 값의 단위가 현실 소재의 단위와 대응하지 않는다.

06

Self-critique / 완성보다 다음 질문

Strongest

계산을 장면 뒤에 숨기지 않았다.

질문, 조작, 수치, 구현 경계를 한 화면에서 연결해 결과보다 사고 과정을 보이게 했다.

Unresolved

시뮬레이션과 실제 천 사이의 거리가 크다.

현재 계수는 상대 비교에는 쓰이지만 재료의 질량·탄성·마찰을 대변하지 않는다.

Future

코드와 소재 샘플을 같은 표로 기록한다.

실제 주름 샘플의 복귀 시간과 간격을 촬영해 모델의 변화 방향부터 검증할 예정이다.

07

Authorship / 도구를 쓴 방식까지 작업의 일부로

Author role

문제 정의, 범위 설정, 시각 방향, 상호작용의 우선순위, 대안 비교와 최종 판단은 저자의 몫이다. C++ 모델과 인터페이스는 공개 저장소에서 함께 검토할 수 있도록 구성했다.

AI disclosure

생성형 AI는 구현 대안 탐색, 코드 초안과 검토, 문장 편집을 보조했다. 출력은 그대로 결론으로 사용하지 않았으며, 아직 수행하지 않은 사용자 시험이나 소재 검증을 만들어내지 않았다.
